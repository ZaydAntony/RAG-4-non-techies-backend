## 🧠 About Raggit

Raggit is a simple yet powerful Retrieval-Augmented Generation (RAG) system built with curiosity, experimentation, and a bit of obsession with making complex AI feel alive and interactive.

It was born on one of those hot, slow Sundays where I started thinking:

> RAG is everywhere… but why does it still feel so overcomplicated for non-technical people?

So I built Raggit — a system that doesn’t just explain RAG, but *shows it in action* through a playful, visual, and interactive experience.

---

## ✨ Why Raggit?

Because learning AI concepts shouldn’t feel like reading a research paper.

Raggit turns:

- 📄 Documents → into searchable knowledge  
- 🧠 Embeddings → into meaningful retrieval  
- 💬 LLM responses → into interactive conversations  
- ⚡ Pipelines → into a visual experience you can *see working*

All wrapped in a UI that feels more like a product than a backend experiment.

---

## 🏗️ Architecture

Raggit is built using a modern full-stack setup:

### 🔧 Backend
- Django (core API layer)
- Django REST Framework (API design)
- Django Q (background tasks & scheduling)

### 🎨 Frontend
- React (UI & interaction layer)

### 🧠 AI / Retrieval Layer
- OpenRouter (LLMs + embedding models)
- Pinecone (vector database for semantic search)

---

## 🧰 Tech Stack

- Django & Django REST Framework
- React 
- OpenRouter API
- Pinecone (Vector Database)
- PostgreSQL (Production)
- MySQL (Development)
- PyPDF (document ingestion)

---

## ⚙️ Features

- 📄 PDF ingestion and processing
- 🧠 Document chunking and embedding generation
- 🔍 Semantic search using vector similarity
- 💬 Context-aware chat with LLM responses
- 🔄 Background processing with task queues - File ingestion
- ⏳ Automatic cleanup of expired sessions
- 🎯 Session-based memory isolation

---

## 🧪 Current Limitations

- No real-time streaming yet (polling-based responses)
- File uploads are currently single-file focused
- WebSockets not implemented (yet 😅, I am living by the principle of "as long as it works")

---

## 🚀 Future Improvements
